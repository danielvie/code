1. What is MNIST?

This tutorial follows the code in app/main.py and the drawing page in web/. The goal is to train a model in Python, export what it learned, and use it to recognize a digit drawn in a browser.

Pictures paired with answers

MNIST is a dataset of handwritten digits. Its name comes from Modified National Institute of Standards and Technology. Every example has two parts: a grayscale image and a label telling us which digit the writer intended.

The data used by this project
PropertyValue
Training set60,000 images used to learn the weights
Test set10,000 separate images used for final evaluation
Image size28 rows by 28 columns, one grayscale channel
Pixel values on diskIntegers from 0, black, to 255, white
LabelOne integer from 0 to 9

A picture of a handwritten seven is the input. The integer 7 is its target. During training the model sees both. During prediction it receives only the picture and must estimate the digit.

Load and scale the images

from torchvision import datasets, transforms

# Convert pixels to float32 values between 0 and 1.
# Also arrange each image as [channel, height, width].
to_tensor = transforms.ToTensor()

training_data = datasets.MNIST(
    root="data", train=True, download=True, transform=to_tensor
)
test_data = datasets.MNIST(
    root="data", train=False, download=True, transform=to_tensor
)

image, label = training_data[0]
print(image.shape)  # torch.Size([1, 28, 28])
print(label)        # The correct digit, stored separately from the pixels

Dividing intensities by 255 changes their scale, not the handwriting. A dark background becomes values near zero; the light strokes become values near one. The label remains an integer. Do not feed the label into the network as an extra input.

download=True downloads missing files and reuses an existing local copy. Run commands in this tutorial from sandbox/python/py_mnist.

2. Turn the image into 784 inputs

The first learned layer in this model is a fully connected layer. It expects a row of input values for each example, not a two-dimensional picture. Flattening changes the shape without changing the pixel values or their order.

Keep different images separate

A batch is a group of examples processed together. With a batch size of 64, nn.Flatten() transforms [64, 1, 28, 28] into [64, 784]. It keeps the first dimension, the batch, and combines the remaining dimensions.

from torch import nn
from torch.utils.data import DataLoader

loader = DataLoader(training_data, batch_size=64, shuffle=True)
images, labels = next(iter(loader))

flat = nn.Flatten()(images)
print(images.shape)  # [64, 1, 28, 28]
print(flat.shape)    # [64, 784]
print(labels.shape)  # [64], one target for each image

Do not use images.flatten() without specifying dimensions here: its default combines the batch too, mixing all the examples into a single long vector.

The model already includes nn.Flatten(). The browser therefore sends [1, 1, 28, 28], not [1, 784]. The exported model performs the same flattening internally.

Does every image model need flattening at the start?

No. This project uses a fully connected network. A convolutional network can process the two-dimensional arrangement directly. Flattening preserves the values and their positions in a fixed ordering, but this dense layer has no built-in concept of neighboring pixels.

3. Follow the signal through the network

The network is a function with adjustable numbers called weights and biases. A forward pass applies that function to the pixels. Training adjusts those numbers; prediction reuses them unchanged.

What each layer actually does

  1. Input: hold 784 pixel values. Flattening has no trainable parameters. Pixel position determines which input gets each value. The input layer does not identify strokes by itself.
  2. Hidden layer: combine pixels into 128 activations. Hidden unit j multiplies each input by its own weight, adds the products and a bias, then applies ReLU. ReLU returns zero for a negative sum and otherwise returns the sum.
  3. Output layer: produce ten logits. Each output combines all 128 hidden activations with another set of weights and a bias. Output index 0 scores digit 0, and so on through digit 9. The last layer has no ReLU or softmax in this model.
For hidden unit j:
    sum_j = b_j + w_j0*x0 + w_j1*x1 + ... + w_j783*x783
    h_j = max(0, sum_j)

For digit k:
    logit_k = c_k + v_k0*h0 + v_k1*h1 + ... + v_k127*h127

For example, a toy hidden unit with two inputs might compute 0.8*0.5 + 0.2*(-1.0) - 0.1 = 0.1. ReLU keeps 0.1. If that sum were -0.3, its activation would be 0. The real hidden units sum 784 terms, not two.

The hidden units may learn useful combinations of pixels, but we do not assign a unit the job of finding a particular stroke. This is a dense network, not a convolutional edge detector.

The diagram as Python

model = nn.Sequential(
    nn.Flatten(),            # [batch, 1, 28, 28] → [batch, 784]
    nn.Linear(784, 128),     # Weighted sums plus 128 biases
    nn.ReLU(),              # Negative sums become zero
    nn.Linear(128, 10),      # Ten raw scores per image
)

The hidden layer learns 784*128 + 128 = 100,480 parameters. The output layer learns 128*10 + 10 = 1,290. That is 101,770 trainable numbers in total. Flatten and ReLU add none.

A score is not yet a probability

Logits can be negative and do not sum to one. To pick a digit, use argmax, the index of the largest logit. To show probability-like scores in the page, apply softmax first. Softmax preserves the winning index and makes the ten scores sum to one.

Even a high softmax score is not a guarantee of correctness. The model must choose among ten digits, so it can confidently label a doodle as a digit.

4. Train and test the model

Before training, the weights are random and the predictions are mostly unhelpful. Training repeatedly asks: which changes to the weights would reduce the error on the labeled examples?

Five operations per mini-batch

The project uses batches of up to 64 images, Adam as the optimizer, a learning rate of 0.001, and three epochs by default. An epoch is one complete pass through the training examples.

import torch
from torch import nn
from torch.utils.data import DataLoader

training_loader = DataLoader(
    training_data, batch_size=64, shuffle=True
)
loss_function = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)

model.train()
for epoch in range(3):
    for images, labels in training_loader:
        # 1. Clear gradients left by the previous batch.
        optimizer.zero_grad()

        # 2. Forward pass: produce ten logits per image.
        logits = model(images)

        # 3. Compare the scores with the correct integer labels.
        loss = loss_function(logits, labels)

        # 4. Backpropagation: calculate gradients for the weights.
        loss.backward()

        # 5. Adam uses those gradients to update the weights.
        optimizer.step()

This is the same update sequence as train_one_epoch() in app/main.py, with the surrounding epoch loop shown together. The project also accumulates batch losses to report a mean for each epoch.

What are loss and gradients?

Loss is a number measuring how poorly the scores agree with the target labels. Cross entropy penalizes a model that gives the correct digit a low probability. PyTorch accepts raw logits and performs the equivalent probability calculation internally in a numerically stable way.

A gradient tells us how a small change to a parameter affects loss locally. Backpropagation computes these derivatives through the output layer and hidden layer. Adam uses them, together with statistics from earlier updates, to choose parameter changes. The learning rate controls their scale.

loss.backward() computes gradients; it does not change the weights. optimizer.step() changes the weights. PyTorch accumulates gradients by default, which is why this simple loop clears them each batch.

Do not add softmax to the model before CrossEntropyLoss. Also do not replace logits with argmax during training: the loss needs the full scores, not just the winning digit.

Evaluate without learning from the answers

test_loader = DataLoader(test_data, batch_size=64, shuffle=False)
model.eval()
correct = 0
count = 0

with torch.no_grad():
    for images, labels in test_loader:
        logits = model(images)
        predicted_digits = logits.argmax(dim=1)
        correct += (predicted_digits == labels).sum().item()
        count += labels.size(0)

print(f"Test accuracy: {correct / count:.2%}")

model.eval() selects evaluation behavior for layers such as dropout, if added later. torch.no_grad() separately turns off gradient tracking. Neither replaces the other. There is no backward pass or optimizer update during this evaluation.

Accuracy is the fraction of correct guesses. Loss also considers how the model distributes its scores. They measure different things. More epochs can eventually overfit: training performance improves while performance on unseen images does not.

Keep test images out of training. To compare architectures or learning rates repeatedly, reserve a validation split from the training data. Select settings using that validation set, then evaluate the final model on the test set.

Run the complete program

uv run -m app.main

# A shorter smoke test, not the model to deploy for best results:
uv run -m app.main --quick --epochs 1

The program prints training loss and final test accuracy, then saves outputs/predictions.png for inspecting individual test predictions. Each training invocation starts a new model.

5. Export the learned model to ONNX

The browser does not need the training data, loss function, optimizer, or Python interpreter. It needs the forward computation and its learned parameters. ONNX, Open Neural Network Exchange, stores that computation as a portable graph with the weights.

Export after training

from pathlib import Path
import torch

path = Path("web/mnist.onnx")
path.parent.mkdir(parents=True, exist_ok=True)
model.eval()

torch.onnx.export(
    model,
    (torch.zeros(1, 1, 28, 28),),  # Example input establishes shape and dtype
    str(path),
    input_names=["image"],
    output_names=["logits"],
    opset_version=18,
    dynamo=True,
    external_data=False,         # Include the weights in this one file
)

This is the export performed by export_model(). The zero image is a shape example, not a new training example. Exporting does not replace the learned weights with zeros or retrain the model.

opset_version=18 selects the ONNX operator definitions used in the graph. It is not the Python, model, or runtime version. The receiving runtime must support those operators.

The contract the browser must follow

Names, shapes, and types of the exported model
BoundaryNameShapeValues
Inputimage[1, 1, 28, 28]float32 intensities, scaled to 0 through 1
Outputlogits[1, 10]Raw scores for digits 0 through 9

The exported batch size is fixed at one because the drawing page predicts one image at a time. ONNX includes Flatten, so the page supplies an image-shaped tensor. Cropping, resizing, and centering the drawing happen outside the exported graph, in JavaScript.

Create the file with this project

uv run -m app.main --export

This command trains, evaluates, and writes web/mnist.onnx. The current network produces a file of roughly 403 KiB. You can reuse it every time the page loads. A new export overwrites it; a fresh checkout needs a new export because the generated model is ignored by Git.

The export is for inference, not a checkpoint for resuming Adam training. It does not include the optimizer's accumulated state.

Verify the boundary

uv run python -m unittest discover -s tests -v

The export test checks the ONNX graph and runs a synthetic image through both PyTorch and an ONNX reference evaluator. Their output logits must agree within floating-point tolerances. The browser smoke test later checks the WebAssembly runtime too.

ONNX is the model; WASM is the execution engine

This project does not compile the Python program into a WebAssembly file. It exports the learned network to ONNX. ONNX Runtime Web supplies a WebAssembly engine that executes that network in the browser.

app/main.py          trains and exports
        ↓
web/mnist.onnx       computation graph + learned parameters
        ↓
ONNX Runtime Web    executes the graph using its WASM backend
        ↓
ten logits          one score per digit

6. Load the model in HTML and predict a drawing

The HTML page provides a canvas and result display. JavaScript prepares the pixels and calls ONNX Runtime. WebAssembly performs the network computation. The static server only delivers files; it does not receive drawings or calculate predictions.

Load the runtime and your application

web/index.html loads these scripts. They are shown here as code, not executed by this tutorial.

<!-- Runtime JavaScript and its WASM assets must use the same version. -->
<script defer
  src="https://cdn.jsdelivr.net/npm/onnxruntime-web@1.22.0/dist/ort.wasm.min.js">
</script>
<script type="module" src="app.mjs"></script>

The runtime exposes ort. Our application waits for the window's load event before creating the session, so the deferred runtime script is available first. It reports a loading error if the runtime or model cannot be fetched.

// Inside loadModel(), after the runtime script has loaded:
ort.env.wasm.wasmPaths =
  "https://cdn.jsdelivr.net/npm/onnxruntime-web@1.22.0/dist/";
ort.env.wasm.numThreads = 1;

const response = await fetch("./mnist.onnx", { cache: "no-cache" });
if (!response.ok) throw new Error("Export the model first.");

const session = await ort.InferenceSession.create(
  await response.arrayBuffer(),
  { executionProviders: ["wasm"] },
);

Create the session once and reuse it for each drawing. Selecting wasm explicitly makes this a CPU WebAssembly example, not a WebGPU example. One thread avoids needing cross-origin isolation headers on the static server.

Make the canvas resemble the training data

The pad is 280 by 280 pixels, ten times the model's input dimensions. Sending those pixels directly would have both the wrong shape and the wrong scale.

  1. Find the bounding box of the light ink. If there is no ink, return no prediction.
  2. Crop to that box and resize with the aspect ratio preserved. Fit the longest side into 20 pixels, leaving a margin in the final image.
  3. Place it on a black 28 by 28 canvas and shift it so its pixel mass is near the center.
  4. Read intensities row by row and divide by 255. Produce a Float32Array containing exactly 784 values.

prepareInput() in web/preprocessing.mjs implements this sequence. Centering by mass means pixels with more ink contribute more to the center calculation. The algorithm approximates MNIST's preparation; it cannot make every drawing match MNIST handwriting.

The data buffer is a flat array in memory, but the tensor shape [1, 1, 28, 28] tells the runtime how to interpret it. The model's own Flatten operation then turns that logical image shape into 784 inputs to the dense layer.

Run the model and read its answer

This simplified function shows the inference part of web/app.mjs. The full page also handles drawing events, blank input, loading failures, and ignoring stale results if you clear or change the pad while a prediction is running.

import { prepareInput, softmax } from "./preprocessing.mjs";

async function predictDigit(session, canvas) {
  const pixels = prepareInput(canvas);
  if (!pixels) return null; // Do not guess a digit for an empty pad.

  const input = new ort.Tensor("float32", pixels, [1, 1, 28, 28]);

  // "image" and "logits" are the names selected during Python export.
  const output = await session.run({ image: input });
  const logits = output.logits.data;

  // Softmax is for the displayed scores, not part of the exported model.
  const scores = softmax(logits);
  const digit = scores.indexOf(Math.max(...scores));
  return { digit, scores };
}
How does softmax convert logits to scores? 
function softmax(logits) {
  const maximum = Math.max(...logits);
  const exp = Array.from(logits, value => Math.exp(value - maximum));
  const total = exp.reduce((sum, value) => sum + value, 0);
  return exp.map(value => value / total);
}

Subtracting the maximum prevents large positive logits from overflowing when exponentiated. It leaves the final probabilities unchanged. A score of 0.9 becomes 90% in the display, but it is not a validated promise of 90% reliability on your handwriting.

Pointer events collect mouse, touch, or pen strokes. After the pen lifts, the application waits briefly, prepares the image, and predicts automatically. The result panel displays the winning digit, all ten scores, and the actual 28 by 28 input.

Try the existing page

uv run -m app.main --export

uv run -m app.serve

Open http://127.0.0.1:8000. Draw a single digit, inspect the small input preview, and compare the predicted digit with what you intended. Use Clear pad before trying another digit. If this tutorial is served at that same address, open the drawing page.

Do not open the drawing application through file://; it fetches the model and imports JavaScript modules. The tutorial itself is a standalone document and can be opened directly. If port 8000 is occupied, use uv run -m app.serve --port 8001 and open that port instead.

Drawings stay in browser memory. Runtime assets currently download from jsDelivr, so the application needs internet access for those assets. The model loads from your static server. This is not a single offline HTML application, and no Python process is involved in prediction.

Keep these boundaries in mind

  • Training learns the weights from labeled examples.
  • Export packages the forward computation and learned weights.
  • Preprocessing makes a new drawing compatible with the model's input.
  • Inference applies the fixed weights to that input. It does not learn from your drawing.
